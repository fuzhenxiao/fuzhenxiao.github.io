Recent Projects

QASM-Eval

QASM-Eval is a dataset for training and evaluating LLMs on hardware-facing quantum programming with OpenQASM 3. It focuses on capabilities that matter in near-term quantum workflows, including timing-aware programming, classical control, pulse-level operations, and mixed workflows that combine these elements in a single program.

The project brings together a training dataset, a benchmark, and simulation-based verification to support the development of reliable LLM assistants for quantum programming.

Two models fine-tuned on QASM-Eval are available on Hugging Face: Llama-3.1-8B-Instruct-QASM-Eval and Llama-3.3-70B-Instruct-QASM-Eval.

Project Overview

QASM-Eval explores code generation beyond static gate-level circuits, covering advanced OpenQASM 3 features that connect quantum algorithms to hardware behavior. Its tasks assess how well models translate natural-language requirements into code within a surrounding quantum program.

The dataset covers four domains, with training and test examples distributed evenly across them:

Dataset Records Domain composition
Training pool 4,000 1,000 timing, 1,000 classical, 1,000 pulse, 1,000 complex
Test 1,200 300 timing, 300 classical, 300 pulse, 300 complex
  • Timing: delays, durations, scheduling constraints, and program timelines.
  • Classical control: measurement, bits, registers, and conditional logic.
  • Pulse control: frames, waveforms, and pulse-level calibration.
  • Complex workflows: tasks combining quantum gates, timing, pulse control, and classical logic.

QAgent

QAgent is a multi-agent framework for autonomous OpenQASM programming. It turns high-level user requests into quantum programs by combining task planning, specialized coding agents, retrieval-augmented generation, and hardware calibration. The project explores how collaborating LLM agents can support the full workflow from a programming goal to validated OpenQASM code.

Contributions

  1. Schema-aware planning and correction for quantum modules. A two-part planning agent (Planner + Criticizer) transforms high-level user goals into task graphs with schema-based validation and automatic corrections.
  2. Agent routing strategy for OpenQASM generation. A routing mechanism assigns tasks to specialized coding agents—Guided Few-Shot Agent and Tools-Augmented Agent—based on quantum task complexity and the capability of LLM base models.
  3. Automatic quantum hardware calibration. A Calibration Agent generates or edits device-specific calibration scripts, bridging high-level user intent with real-device execution constraints.
  4. End-to-end workflow with structured reporting. Comprehensive reporting consolidates schemas, chosen strategies, calibration results, and generated OpenQASM code.

Workflow Overview

Specialized agents work together across planning, code generation, and calibration:

  • Plan Agent: breaks a request into quantum kernels and refines an initial plan into a graph with validated parameters.
  • Calibration Agent: calibrates quantum backends based on the user's request.
  • Guided Few-Shot Coding Agent: handles common, well-structured kernels and uses a test-reflection loop.
  • Tools-Augmented Coding Agent: handles complex or novel kernels that require additional tools, using testing and reflection to refine the code.
  • Retrieval-Augmented Generation Module (RAG): provides examples, schemas, and tools from the database to support planning and execution.

The final output is a set of OpenQASM scripts and reports tailored to user requirements.

Coding Agent Workflow Loop

  1. The Advisor provides guidance and high-level strategies for code generation.
  2. The Coder writes the corresponding OpenQASM code.
  3. The code is executed via simulation and testing.
  4. A structured report is generated with results and feedback.
  5. The Reviewer examines the output. If it is correct, the workflow proceeds; otherwise, the reviewer provides feedback to the coder.
  6. The Coder refines or rewrites the code.
